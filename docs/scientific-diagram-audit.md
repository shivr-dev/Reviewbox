# Scientific diagram audit

Scope: read-only review of the existing semantic schema, subject/math/optics renderers, ray adapter, expression evaluator, importer, and author preview. Findings describe the baseline inspected on 2026-11-01; concurrent implementation may supersede individual items. No runtime or test files changed by this audit.

## Confirmed correctness gaps

| Priority | Location / trigger | Consequence and required invariant |
| --- | --- | --- |
| P1 | `subject-diagram.tsx`, force magnitude clamp | 1 N and 100 N become 42 px and 96 px. A quantitative diagram must use a common linear scale, with explicit labels for very small arrows; a schematic must clearly avoid implying magnitude ratios. Missing magnitude must remain unknown rather than compete numerically with known forces. |
| P1 | `ray-optics-adapter.ts`, height-dependent determinant tolerance | Probe `f=10,u=30,h=1e-12` returns an infinite image and says the object lies at the focal plane. Expected `v=15,m=-0.5` independently of nonzero object height. Classify focal singularity from scale-aware `u-f`, then intersect rays robustly. |
| P1 | Geometry validation accepts coincident endpoints in dimension/angle/auxiliary marks | `dimension:['A','A']` validates; `MathDiagram` normalizes a zero vector. Tangent validation with a coincident second point evaluates a NaN ratio and can incorrectly accept it. Every rendered direction vector needs distinct finite endpoints. |
| P1 | `buoyancy`, unconditional fixed force arrows | The upward/downward arrows are always 80/90 px, even at submerged=0. This invents a force ratio and an upward liquid force without liquid displacement. Require quantitative density, displaced volume, gravity and external-force data before solving; otherwise use clearly schematic arrows and preserve unknowns. |
| P1 | `forces` validation and tilted body origins | Friction at center passes; normal/friction on `surface:none` pass. `surface:horizontal` friction incorrectly uses an irrelevant supplied incline. `top` is not rotated with the body. Friction contact origin and actual surface tangent/normal must agree with drawing coordinates. A missing incline must not silently become a quantitative horizontal plane. |
| P1 | `optics` schema requires objectHeight | Missing height rejects a legitimate schematic lens question. Default height inside renderer must not become a measured height or a computed answer. Separate schematic normalization from quantitative evidence; preserve the unknown field in import/export. |
| P2 | Rotated plane mirror image metadata | At angle 45 degrees, image base is approximately `(0,-30)` and tip `(3,-30)`, while metadata still says distance=30,height=3. These are equal mirror-relative lengths, not x-axis image coordinates. `showDistances` currently places v along the x axis. Declare coordinate conventions and draw perpendicular object/image distances to the mirror, or restrict the supported mirror orientation. |
| P2 | Circuit validator checks IDs/references only | Distinct node IDs may share coordinates, component IDs may repeat, and crossing wires have no declared junction semantics. Reject zero-length drawn components and duplicate IDs; preserve graph connectivity independently of appearance. A deliberately wrong student circuit must remain representable, with diagnostics rather than compulsory correction. |
| P2 | `diagram-expression.ts` validates at one x | `x^x` validates at x=.371 but throws when evaluated at x>20. An accepted spec can fail during rendering. Distinguish unsupported syntax from domain gaps and exponent limits; render domain gaps as broken traces, and reject expressions that cannot be safely evaluated over supported ranges. |
| P2 | Numberline/statistics rendering | Numberline x positions depend on array index, not data value. Values 1,2,100 become evenly spaced. A quantitative numberline must project numeric values. |

## Deterministic acceptance cases

These are proposed tests, not tests executed by this audit. Besides numerical results, inspect SVG primitives, labels and phase visibility; finite SVG alone is insufficient.

- **Modes/provenance:** quantitative fields require explicit consistent units and source evidence; schematic missing dimensions stay missing through parse/import/export; construction hides derived answers until their declared stage. An unsupported mode/kind must produce a visible error, never a silently simplified drawing.
- **Phase matrix:** for every answer-bearing primitive, test question/hint/solution against each declared phase. A hint remains visible in solution; solution values never affect question labels, arrow scale, axis bounds, accessible names or exported SVG. Reusing one spec across phases must not retain old hidden DOM content.
- **Measurement:** ruler range `[0,10]`, minor=.1, majorEvery=10, object endpoints 2.3 and 7.8 => length=5.5, not end reading 7.8. Cover reversed endpoints, negative ruler origin, nonzero origin, object exactly on last tick, very small minor increment, unit conversion, and object outside ruler. A count of N stacked sheets/coils divides the total by N; count=0 rejects. Cap tick count before iterating.
- **Sound:** hold frequency fixed and double amplitude: zero crossings/period stay unchanged and excursion doubles under the same y scale. Hold amplitude fixed and double frequency: excursion stays fixed and cycles double under the same x scale. Time view in ms converts to seconds; space view uses wavelength, not an arbitrary frequency without propagation speed. Zero amplitude is a useful flat signal, not necessarily invalid. Do not infer perceived loudness from amplitude alone.
- **Motion:** points `(0,0),(1,2),(4,8)` must plot time intervals in ratio 1:3. For s-t, slope gives velocity; for v-t, signed area gives displacement. Test rest, negative velocity, reversal, duplicate/out-of-order time, unequal sampling, and gaps. Do not infer acceleration from ordinal spacing. Reject contradictory constant direction only when the model actually asserts unidirectional motion.
- **Optics:** convex u=3f => v=1.5f,m=-.5; u=2f => v=2f,m=-1; u=.5f => v=-f,m=2; concave u=3f => v=-.75f,m=.25. Test u=f, u=f±small relative epsilon, and heights spanning several orders. Changing height must not change v. Missing height in schematic mode must not print a made-up value. Test reflection at 0/45/90 degrees; Snell at signed angles, equal indices, normal incidence, critical angle and either side. Bounds must include finite visible geometry without allowing a hidden computed image to disclose the answer through rescaling.
- **Forces:** common-scale lengths for 1/2/100 N; rotate incline through -30/0/30 degrees and compare gravity vertical, normal perpendicular, friction tangent, and all attachment points. Zero net force does not imply all forces absent. Unknown forces have no inferred numeric magnitude.
- **Lever/pulley:** signed moments for downward 10 N at x=-2 and downward 20 N at x=1 balance about pivot 0; swapping a force direction reverses its moment. Force=0 draws no arrow. Include zero moment arm, unequal scales/units, and near-zero torque with a relative tolerance. For an explicitly ideal pulley, count moving-load supporting rope segments and compare `F=W/n`; fixed pulley changes direction only. Do not assume frictionless/massless/taut or infer n from icon count. A supported-load group must be explicit.
- **Fluids:** displaced volume 0 gives liquid buoyancy 0; full submersion gives rho*g*V. Equal-depth pressure in the same static liquid agrees; gauge pressure at free surface is zero and must be distinguished from absolute pressure. Mass/density/volume contradictions must surface; floating equilibrium requires force balance rather than an arbitrary submerged fraction. Restrict unsupported accelerating/compressible/multifluid cases.
- **Circuit:** separate topology tests from physical-suitability diagnostics. Test dangling endpoints, duplicate IDs, coincident nodes, wire crossings with/without junction, open switch, source short, ammeter across source, and voltmeter in series. Ideal-meter assumptions and source polarity must be explicit before solving. Question-stage display must not substitute corrected connectivity.

## Compatibility and verification boundaries

- Existing Zod object schemas strip unknown keys. Adding mode/phase/evidence only to a renderer or separate schema loses those fields when the importer or `Diagram` reparses the old semantic union. Audit the complete parse/persist/render/export route for every new field, including nested arrays.
- The top-level `Diagram` dispatcher reparses and routes only existing kinds; `SubjectDiagram` receives no stage. New kinds and stage rules must reach all dispatchers and author preview, plus print/export and saved packs.
- Existing import guidance only documents lens optics and old motion/force/buoyancy formats. It must describe new units, data provenance, unknowns and per-kind modes without changing old-pack interpretation.
- Existing legacy `function_graph` migration drops `showAxes:false` and changes an omitted grid flag into false. Preserve old semantics intentionally or document the migration; do not silently discard usable old presentation data.
- Existing tests rendering `SubjectDiagram` directly can pass for optics while drawing no optics primitives: that component has no optics branch. Test the routed optics renderer or its drawing component and assert meaningful object/lens/ray content.
- Computational checks do not verify mobile clipping, high-density ruler ticks, long labels, grayscale contrast, JSXGraph load errors or export equivalence. Those need visual inspection at representative sizes.

Executed diagnostic probes: tiny-height lens singularity, rotated mirror image metadata, coincident dimension validation, and friction at center validation. No claim of full suite or visual acceptance is made.
